# cellprotect

奖学金获奖人口统计报表的小单元格保护模块（纯标准库，无外部依赖）。

## 接口

- `BuildReport(records, attribute)`：过滤（仅 Approved/Disbursed）、按学生去重、
  CIP 前两位作部门、按固定枚举（含「未申报」）交叉计数，随后调用 `Protect`，
  返回内部结果与可发布表。
- `Protect(counts)`：1..4 的格子为主抑制；再追加必要的补充抑制，直到每个主格
  的可行域包含 0 或 >=5。结果用 `Published/Primary/Complementary` 标注原因；
  对外发布形态只有「公布数值 / 已抑制」两种状态。合计始终公布。
- `FeasibleRange(published, row, col)`：仅依据发布形态，求某个被抑制格子的最小、
  最大可能取值（非负整数，且满足所有公布格与全部合计）。

## 方法

不枚举任何可能的表，也不使用「每行每列至少两个抑制」这类局部计数规则。
把所有公布格的数值从行/列合计中扣除，得到残量；抑制格构成二部图
`源点 -> 部门 -> 属性取值 -> 汇点`（部门-属性边容量无穷），真实表给出一个饱和流。
对抑制边 e：

- 最小值 = 总残量 T − 删除 e 后的最大流；
- 最大值 = X − T，其中 X 是「删除 e 后，再加入两条无穷边把部门逼到汇侧、
  把属性逼到源侧」网络的最大流（最小割）。

最大流用 Dinic 实现，全部为多项式时间。

`Protect` 先检查全抑制（全抑制仍保护不了才拒绝发布并给出原因）；否则按
行主序确定性地贪心选择「单独补它能修复最多主格」的格子，最后按添加逆序做
极小性后处理：任何补充抑制若单独改回公布都不会再使某个主格失保，就删除它。
因此每个保留下来的补充抑制都是必要的，且重复调用输出完全一致。

## 文件

- `types.go`：枚举、记录、内部/发布结构。
- `report.go`：属性枚举、归一化、部门提取、计数去重、发布形态转换。
- `flow.go`：Dinic 与抑制边可行上下界。
- `protect.go`：主抑制判定、贪心补充、拒绝与极小性。
- `feasible.go`：对外的可行域计算。
- `cellprotect_test/`：
  - 暴力枚举器（4x4、总计<=12）对随机小表做三项验证：保护标准+极小性、
    `FeasibleRange` 与枚举完全一致、被拒绝表在全抑制下确实违规；
  - 两张手工表（每行每列两抑制仍被合计锁定；合计为 0 的列陷阱）；
  - `BuildReport` 语义、确定性、拒绝与性能（40x8）测试。
